# 硬件综合评审

把审查对象绑定到版次、工程目录、平台、待检指标和已获许可。默认基于现有证据，只需单项审查时选择对应专项。用户明确需要综合结论时，用下面的流程。

1. 建立证据表，区分设计值、原厂保证值、求解结果和实测。记录报告覆盖的板号、固件版本和工况。
2. 检查电源时序、脚网与封装映射、关键网的层叠和回流、热与保护、装配约束、临界料和可测性。以同版文件和测试条件说明每个发现。
3. 报告优先级、影响位置、复现或核对方法、修复责任及关闭证据。结论用 `Go`、`Hold` 或 `No-Go`，并给出适用范围和未核项。
4. 做故障分析时，先写可被验证或排除的假设和测量方案。授权范围内取证，按共同的时间基准关联总线、波形和固件日志，再把证据交给源头专项复验。

对电气安全或标准条款需要引用时，核对适用版次和正式来源。使用 [评审记录骨架](assets/review-evidence.json) 留痕。现场取证和修改依据 [权限门禁](../hardware/references/permission-gates.md)。工厂上传、付款和下单由各自授权决定。
