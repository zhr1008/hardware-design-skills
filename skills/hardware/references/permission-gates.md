# 电子硬件操作的许可边界

按工具和本次参数的实际效果定级。检查目标身份、作用范围、自动保存或派生输出、模态交互、外部发送和设备状态变化。一次调用包含多个动作时，按其中最高一级处理。当前请求、已有具体授权及工具自身的限制共同决定能否执行。

| 级别 | 允许范围与典型动作 |
| --- | --- |
| L0 离线 | 读取已保存的工程、库、已有报告、日志、抓包和波形，做静态审查、核算及准备。离线库读取受服务器 `allowed_paths` 限制。 |
| L1 现场只读 | 定向读取活动工程、实际打开的文档、未保存状态、已生成的检查结果，查询渠道公开物料、库存和数量价。只读桥接按现场对象与所需信息收窄。 |
| L2 指定副本或有界本地执行 | 在指定隔离副本中写入或仿真，在有界的本地目录生成输出，构建已指定目标，或运行同一已确认工程的非模态原生编译且禁止保存设计源。正常编译可能更新派生文件或消息，按工具契约交代影响。 |
| L3 原工程、界面、硬件或外发 | 写入原工程、原库或用户已打开的文档，包括编辑后尚未保存的状态、强制保存以及会改动源对象的命令。模态原生 DRC、Computer Use、控制设备或改变总线、向外部上传、提交、下单及付款按各自的具体动作授权。任何可能切换前台焦点、显示交互对话框或发送键鼠输入的操作同样需要具体授权。 |

## 从当前请求确定入口

- 普通只读审查从现有保存文件开始。离线证据缺少所需现场事实时，先请求允许对指定工程进行 L1 只读桥接，说明缺少的数据。用户明确要求查看当前已打开的 Altium 工程或板卡时，请求已包含相应 L1 只读桥接，可直接确认活动项目和目标文档后读取。若用户限定离线，保持该范围。
- 日常选型、查料、查库存或数量价可以直接使用 `components` 的 L1 查询。按用户给定的渠道、数量和物料规格收窄请求。修改本地库、上传 BOM 或进入账户内的实际采购流程时，按对应动作重新对照授权。
- 从只读进入 L2 写入、构建或原生编译，或进入 L3 的现场写入、界面和其他高影响动作，分别核对具体授权，缺失时在执行前询问。已经明确要求对指定对象做该项操作时，沿用同一授权。活动项目发生切换时先核对对象身份。
- Altium 桥接不足时，先核对工具目录、适用参数和已保存的替代证据。确需 UI 时请求独立的 L3 UI 授权，列出窗口、对象与拟执行的具体界面动作。获准后使用实际暴露的 Computer Use 入口，本机为 `mcp__cua_repl.js`。通过 `eda_agent` 的菜单、画布、对话框等操作驱动界面同样适用。界面查阅授权仅覆盖界面查阅，写入、保存和模态命令分别核对范围。
- 离线库因 `allowed_paths` 拒绝路径时，暂停该库上的动作，请用户确认要授权的目录，或指定已有允许目录中的副本。需要改服务器配置时须有该项授权并通过受支持的方式处理。确认前禁止用其他解析器、文件读写、桥接或 UI 继续访问该库，也禁止借目录拒绝改写原文件。恢复后核对解析后的绝对路径和库件身份，再按授权读查或写副本。

## 容易误判的操作

### Altium 编译和设计检查

- `altium.get_erc_violations` 默认 `compile=true`，会编译工程，可以采用打开态的未保存图纸，并可能刷新派生的 `.PrjPcbStructure`。仅查已打开且聚焦工程的缓存时，先只读确认工程身份，传 `compile=false` 并省略 `project_path`，再核返回路径和 `compiled`。即使禁用编译，传入一个尚未打开的 `project_path` 也可能触发打开工程。区分缓存与当前编辑态、未保存页和缺失文件。`eda_agent.proj_compile` 等无源写入的同工程非模态原生编译按 L2 处理。
- `eda_agent.proj_get_nets`、`proj_get_connectivity` 和 `proj_get_connectivity_many` 的签名涉及编译，即使没有强制重编译也须核对 L2。`force_recompile=true` 包含保存未保存文档，按 L3。只有 L1 时可做 `proj_get_compile_freshness`、`proj_get_erc_violations`、`pcb_get_clearance_violations` 等定向查阅，按实际签名确认结果覆盖和新鲜度。
- `eda_agent.design_review_snapshot` 的 `force_recompile`、`run_erc` 和 `run_drc` 默认关闭。明确请求 `sections` 中的 `erc` 或 `drc` 仍会分别触发检查，按其实际副作用定级。`force_recompile=true` 会调用 `SaveAll`、使编译缓存失效并重新编译，按 L3 处理。默认的 `design_stats`、`diff` 及默认附加的 `bom` 会调用 `SmartCompile`，缓存未命中时可能原生编译。只获 L1 时使用已确认的定向只读接口，或只选择已核实无上述副作用的 section 并显式关闭 `include_bom` 和三个触发开关。请求含可能正常编译的 section 时按 L2 核对授权。
- `eda_agent.pcb_run_drc` 会打开阻塞桥接的模态对话框。使用 `allow_modal=true` 需要该项 L3 授权以及人在现场可处理对话框。`altium.run_drc` 会处理原生对话框，Altium 可能写入并打开报告、更新板上违规标记，也属于 L3。先检查已保存报告或用只读接口读取存量违规。执行后用桥接返回的 `ran` 或 `drc_triggered` 和可取得的原生报告确认检查确实执行，记录规则、结果范围及截断情况。仅返回零条不足以确认检查通过。

### SPICE 与 SOLIDWORKS 前台和外发许可

- **前台动作必须先获批。** 按实际代码、命令、应用行为和参数判断，包括由命令、COM、MCP、脚本或子进程间接产生的效果。可能打开或激活前台窗口、抢占输入焦点、弹出交互对话框或模拟键鼠时，按 L3 说明目标应用、拟执行动作和影响范围，等待用户批准后再执行。无法确认不会影响前台时，也按此规则暂停对应动作。安装、连接、生成脚本、授权后台执行和挂起后的自动回退均不覆盖前台动作。已有的同一具体前台授权可复用。
- `ltspice-mcp` 优先使用已验证的后台 CLI 后端，确认任务授权的输入和输出路径并按 L2 处理实际仿真。执行来源不明的网表前，核对能运行外部程序的语句及其递归导入。工具白名单只约束 MCP 入口。打开原理图界面、联动运行中的 LTspice 或切换到可能唤起窗口的后端时，须先按 L3 获批。若后台引擎不可用，报告实际缺口并继续离线准备。按实际引擎、波形及量测值验收。
- **模型优先在本机处理。** 先查本机 SOLIDWORKS SDK 或公开帮助。`swapi-pilot` 经本机代理仅转发公开 API 标识。C# 模板、脚本和模型文件在本机生成或处理。禁止默认外发 `.SLDPRT`、`.SLDASM`、STEP 等 3D 文件、几何或编码数据，以及本机路径和项目资料。确需将已命名文件或数据发往服务器时，先说明文件、接收方、用途与范围，等待用户对该外发动作的 L3 批准。查公开 API、安装 MCP、执行本地 COM 和前台操作的授权，各自独立于外发审批。
- 实际 `dotnet run` 或 COM 操作为独立执行步骤，先检查脚本及关键参数。已明确不启动前台、不切换焦点的持续会话只读或隔离副本执行，分别按 L1 或 L2 核对。可能启动可见进程、激活文档、切换焦点或弹出交互对话框时按 L3。`Silent` 选项只覆盖其 API 声明的行为，需同时核对脚本其余步骤和宿主条件。

### Multisim、制造和台架

- Multisim 已有文件和仿真结果可离线核查。先确认实际后端和输出路径，`runtime_status` 可探测兼容性。经核实不会启动应用、切换文档或执行仿真的 COM 定向读取按 L1，自动转入时先请示。仅对指定隔离副本运行、有界输出且无交互的仿真归 L2。接管现有 COM 会话、修改或保存原文件、控制界面时按 L3。工具若要求批准不可变网表预览，按实际网表摘要绑定该批准，再执行已授权的下游步骤。原生扫参按工具要求确认候选范围及批准，读回初值恢复和实际波形。原生工程的验收使用实际保存与重开证据。
- 嘉立创的公开物料及装配库查询归 L1。嘉立创或 Fictiv 的本地资料准备和制造包检查按 L0/L2 处理。用 Computer Use 操作账号界面、上传 Gerber/BOM/CPL/CAD、申请正式报价、提交订单和付款按 L3 核对各自授权的文件版本、接收方、订单或金额与截止阶段。以真实预览、状态或回执核对已执行的动作。
- 固件离线分析归 L0，有界本地构建归 L2。连接编程器执行烧录、擦除、解锁、复位等按 L3 核对目标板、芯片、探针、镜像、地址范围和动作。全片擦除、选项字节及保护位以明确授权范围为准。完成后按任务检查回读、启动状态或目标板反馈。
- 已录制的 CAN、Modbus、串口或仪器数据可离线分析。只有能确认保持被动、对目标状态和总线没有影响的现场监测才按 L1。检查串口握手线（DTR/RTS）、CAN 控制器的只听模式及 Modbus 读取是否实际发出请求。打开端口可能复位设备、向总线发帧、写寄存器、经串口 shell 发命令、控制设备或启停仪器输出时，按 L3 核对设备、接口、地址、报文或设置、运行范围及终止条件。仪器输出核对通道、限幅与负载，在授权条件下读回实际值、响应和结束状态。

## 请求、执行与回读

可直接使用以下询问，并按实际动作填写。

> 已根据〈已有证据〉完成〈本地准备或发现〉。为核实〈具体缺口〉，需从〈当前级别〉升级到〈目标级别〉，用〈入口和关键参数〉对〈工程绝对路径/活动文档/设备/接收方〉执行〈具体动作〉。它会〈实际变化、输出位置、模态交互或外发范围〉，回退边界是〈基线、回退方式或不可逆影响〉。取得〈验收证据〉后停在〈阶段或条件〉。是否允许这一步？

授权跟随实际操作对象、动作、范围和截止条件。同一授权可以覆盖同一对象上的已明确动作和必要回读，也可覆盖边界内的故障恢复。身份、输入版本、写入范围、工具实际副作用或外部接收方变化超过原授权时，只暂停依赖该变化的操作，继续完成仍在范围内的工作。调用失败或超时后先回读现场状态，确认操作是否已发生再判断是否能够重试。实际写入核对目标、变更及持久化证据，外发与设备动作核对回执或测量反馈。权限、环境或证据仍有缺口时，说明完成到的阶段及尚待核实的结果。
