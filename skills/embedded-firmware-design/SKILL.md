# 嵌入式固件设计

按 [工程决策](../hardware/references/design-workflow.md) 绑定同版 BSP、引脚、复位默认态、采样定时及故障行为。变更回流电路和试验。离线构建、实际烧录和板上证据各自处理。

从目标板版次、实际芯片型号、SDK 与编译器版本开始。先核对原理图和固件配置，列出接口的网络名、引脚复用、有效电平、供电域、复位状态、时钟和外设依赖。区分通用实现与板级差异。

1. 从项目内的配置、同版本 SDK 示例或厂商资料确定 API。保持已有初始化顺序、IRQ 与 DMA 生命周期和低功耗约束。
2. 明确每个状态的触发、超时、错误返回和安全输出。记录资源所有权以及中断、任务和 DMA 回调之间可观察的数据竞争。涉及 I/O、存储或通信时处理设备离线与重试上限。
3. 针对症状留最小诊断和可复现实验。测试缓冲区边界、重启、超时、资源释放，再用匹配的构建技能生成指定镜像。
4. 分别说明源码修改、构建结果、仿真与实板证据。编译仅证明该配置可构建。检查生成的 ELF、MAP 或目标镜像及其路径和摘要。
5. 物理验证由明确的板号、探针/端口、镜像和停止条件约束。执行前按[硬件操作权限](../hardware/references/permission-gates.md)核对上电、复位、烧录、前台及外发。

遇到电平、引脚和上电时序变更，把目标版次、修改原因和测试工况回传 PCB、电路和联调环节。使用 [工具链入口](../embed-ai-tool/SKILL.md) 分流实际执行。
